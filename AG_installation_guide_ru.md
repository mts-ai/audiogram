# Термины и сокращения

| **Термин** | **Описание** | 
| ------ | ------- |
| Бакет (S3) | Базовый контейнер в объектном S3-хранилище, предназначенный для хранения неограниченного объема данных. | 
| Нереляционные базы данных | Системы хранения данных, не использующие табличную структуру (SQL). | 
| Рабочий узел (worker node) | В Kubernetes – виртуальная или физическая машина, выполняющая контейнеризированные приложения. | 
| Реляционные базы данных | Базы данных, организованные в виде связанных таблиц со строками и столбцами, использующие язык SQL для управления данными. | 
| Управляющий узел | Узел в Kubernetes, управляющий всем кластером. Он следит за остальными узлами и распределяет между ними нагрузку. | 
| Apache Kafka | Распределённый программный брокер сообщений для обработки потоковых данных в реальном времени с высокой пропускной способностью и низкой задержкой. | 
| ClickHouse | Реляционная аналитическая база данных, позволяющая выполнять аналитические запросы в режиме реального времени на структурированных больших данных. | 
| CPU core | В Kubernetes – абстрактная, относительная мера мощности CPU, эквивалентная 1 физическому или виртуальному ядру на узле. Ресурсы CPU управляются как сжимаемый ресурс в единицах, называемых миллиядрами (m, millicores). |
| CPU узел | В Kubernetes – рабочий узел на котором единственным рабочим ресурсом является CPU (но не GPU).| 
| Docker | Oткрытая платформа для разработки, доставки и запуска приложений в изолированных контейнерах. | 
| Elastic Stack | Набор инструментов, включающий Elasticsearch, Kibana, Beats и Logstash, предназначенный для сбора, поиска, анализа и визуализации данных из любых источников в режиме реального времени. | 
| GiB (напр. 4.0 GiB) | От англ. Gibibyte. В Kubernetes – единица измерения, используемая для указания запросов и ограничений на использование оперативной памяти для контейнеров и подов. | 
| GPU узел | В Kubernetes – рабочий узел на котором основным (наиболее мощным) ресурсом является GPU (графический ускоритель). | 
| Ingress Controller | Специализированный балансировщик нагрузки и обратный прокси-сервер (обычно NGINX, HAProxy или Traefik), который управляет внешним HTTP/HTTPS-трафиком, поступающим в кластер Kubernetes. | 
| Keycloak | Система управления идентификацией и доступом, обеспечивающая единый вход (SSO), аутентификацию и авторизацию для приложений. | 
| KeyDB | Хранилище данных в оперативной памяти, используемое в качестве базы данных, кэша и брокера сообщений. | 
| Kubernetes | Система для автоматизации развёртывания, масштабирования и управления контейнеризированными приложениями. | 
| m (напр. 250m) | От англ. millicores. Единица измерения, используемая в Kubernetes для определения долей ядра (core) процессора. | 
| MiB (напр. 256.0 MiB) | От англ. Mebibytes. В Kubernetes – единица измерения, используемая при определении запросов и ограничений на использование памяти для подов и контейнеров. | 
| MIG-профиль | От англ. Multi-Instance GPU. Это шаблон, по которому видеокарта NVIDIA может быть разделена на изолированные части. Далее каждая часть закрепляется за определенным сервисом, в результате чего этот сервис получает свой выделенный ресурс видеопамяти. | 
| PostgreSQL | Oбъектно-реляционная система управления базами данных. | 
| S3-хранилищe | Высокомасштабируемое облачное объектное хранилище, использующее API Amazon S3 как стандарт для работы с неструктурированными данными. Данные хранятся в бакетах (контейнерах) в виде плоских объектов, что обеспечивает гибкость, надежность, тройную репликацию и доступ по HTTP/HTTPS. | 

# Об Audiogram

Audiogram – это продукт микросервисной архитектуры на базе нейронных сетей и методов машинного обучения.

Функции Audiogram:

| **Название функции** | **Описание** | **Режимы работы** | 
| ------ | ------- | ----- |
| Синхронное распознавание речи | Распознавание речи – это преобразование аудиосигнала в текст. <br> При синхронном распознавании в Audiogram отправляется запрос с аудиоданными, речь из которых необходимо распознать (например, запись диалога между оператором и покупателем). <br> Audiogram обрабатывает полученное аудио и возвращает распознанный текст в ответе на запрос. Во время распознавания речи Audiogram позволяет также: <ul> <li> Определить является ли речь настоящей или была синтезирована искусственно. </li> <li>Определить пол, возраст и эмоциональный настрой говорящего.</li> <li>Проводить диаризацию речи (разделять фразы по спикерам, которые их произносят).</li></ul>  | Распознавание речи может осуществляться в **файловом** или **потоковом** режимах: <br> **Файловый режим**: в запросе на распознавание отправляется готовый аудиофайл. Audiogram обрабатывает его целиком и возвращает результат. Этот режим подходит, например, для распознавания записей лекций или собраний. <br>**Потоковый режим**: это процесс распознавания речи в реальном времени. Когда говорящий начинает беседу, его речь тут же по кусочкам отправляется в Audiogram на распознавание. Audiogram возвращает результаты распознавания также частями, по мере поступления новых порций. Этот режим подходит для создания голосовых помощников. | 
| Асинхронное (отложенное) распознавание речи | Эта функция подходит для распознавания больших аудиофайлов (объемом до 1 ГБ). <br>Чем больше размер аудио, тем дольше может занимать процесс распознавания (до 8 часов). <br>Асинхронное распознавание проходит следующим образом:<ol> <li> Аудиофайл сохраняют в S3-совместимое хранилище, которое использует Audiogram.</li><li>Посредством gRPC API ставится задача на отложенное распознавание.</li><li>Через некоторое время необходимо проверить статус задачи. Если задача выполнена, результат распознавания можно скачать из S3-хранилища.</li></ol> |  | 
| Синтез речи | Синтез речи – это озвучка текста. <br> При синтезе в Audiogram отправляется запрос с текстом, который необходимо озвучить, и параметрами озвучки (каким голосом, интонацией и т. д.). <br>Audiogram обрабатывает запрос и в ответе возвращает аудиофайл с озвучкой. | Синтез речи может осуществляться в **файловом** или **потоковом** режимах: <br> **Файловый режим**: В запросе на синтез отправляется весь текст целиком. Audiogram обрабатывает запрос и возвращает аудиофайл с озвучкой. Этот режим подходит, например, для озвучки книг, комментариев к видео. <br>**Потоковый режим**: В этом режиме текст поступает на синтез частями. Audiogram выполняет озвучку также по частям, по мере поступления новых порций. <br>Потоковый режим синтеза речи подходит для создания голосовых помощников, когда надо имитировать живое общение без неестественных пауз. |
| Клонирование голоса | Audiogram поддерживает технологию клонирования голоса. ЕЕ можно использовать, например, чтобы обучить автоответчик говорить голосом владельца номера.<br> Можно просто клонировать голос человека (для этого понадобится несколько минут записи оригинального голоса). А можно создать полноценную модель голоса (Brand Voice) - для этого понадобится около 10 часов записи желаемого диктора. Такой голос будет максимально похож на оригинал. <br> Для клонирования голоса в Audiogram отправляется запрос с аудиоданными, речь из которых необходимо клонировать.<br> Audiogram создает задачу, по исполнении которой создается новый голос. Далее его можно использовать при синтезе речи. |  | 
| Накопление и возможность использования данных для улучшения ML-моделей для распознавания речи или исправления некорректной работы Audiogram | Входящие данные для распознавания речи и данные, созданные в результате распознавания, сохраняются в S3-совместимом хранилище, которое использует Audiogram.<br> Далее эти данные можно использовать для улучшения/дообучения ML-модели, отвечающей за распознавание речи, или, чтобы разобраться в причине некорректной работы Audiogram. |  | 
| Управление клиентами и просмотр статистики | Audiogram можно использовать в рамках одной компании или же в мультитенантном режиме.<br> Управлять пользователями и просматривать статистику использования Audiogram можно через консоль администратора Audiogram. Консоль администратора представлена в виде веб-клиента и открывается в любом браузере. |  |

# Требования к DevOps-инженерам

Установку Audiogram необходимо выполнять DevOps-инженерам со следующими компетенциями:
- опыт администрирования Linux;
- опыт развертывания и поддержки решений микросервисной архитектуры;
- навыки работы с Kubernetes и helm;
- навыки работы с Apache Kafka, Apache Superset, PostgreSQL, KeyDB, ClickHouse, Keycloak, S3-совместимыми хранилищами.

# Структура Audiogram

Чтобы лучше понимать процесс установки Audiogram, в первую очередь стоит разобрать его структуру.

Audiogram состоит из 5 модулей:

| **№** | **Название модуля** | **Описание** | 
| ------ | ------- | ----- |
| 1 | asr | Содержит микросервисы, отвечающие за распознавание и отложенное распознавание речи, а также микросервисы, позволяющие:<ul><li>определить является ли речь подлинной или синтезированной;</li><li>определить пол, возраст и эмоциональный настрой говорящего;</li><li>провести диаризацию речи (разделение фраз по спикерам, которые их произносят).</li></ul> | 
| 2 | tts | Содержит микросервисы, отвечающие за синтез речи. | 
| 3 | common | Содержит микросервисы, которые используются микросервисами других модулей. | 
| 4 | media | Содержит микросервисы, отвечающие за работу архива, в котором хранятся аудиоданные, поступившие в запросе на распознавание речи, результаты распознавания, а также метки и данные других микросервисов модуля asr. | 
| 5 | iam | Содержит микросервисы, отвечающие за аутентификацию и авторизацию пользователей. |

> Для промышленного использования все микросервисы, входящие в состав Audiogram, должны быть установлены в Kubernetes-кластере.<br>
Во время работы некоторые микросервисы обращаются к различным базам данных и к S3-совместимому хранилищу. Эти базы данных и хранилище должны быть развернуты снаружи Kubernetes-кластера.

## Сервисы asr

Модуль **asr** содержит микросервисы, отвечающие за распознавание и отложенное распознавание речи, а также микросервисы, позволяющие:
- определить является ли речь подлинной или синтезированной;
- определить пол, возраст и эмоциональный настрой говорящего;
- провести диаризацию речи (разделение фраз по спикерам, которые их произносят).

| **№** | **Модуль** | **Сервис** | **CPU/GPU**|**Описание**|
| ------ | ------- | ----- |----- |----- |
| 1 | asr | api | CPU | gRPC API для получения услуг распознавания речи. |
| 2 | asr | grpc-gateway | CPU | Сервис выполняет преобразование RESTful запросов в gRPC. |
| 3 | asr | e2e | GPU | Сервис выполняет распознавание речи. Состоит из 2 компонентов - agent и server. Server - это NVIDIA Triton сервер, на котором работает модель распознавания речи. Agent выполняет роль посредника между API и Server, так как они не могут взаимодействовать напрямую. |  
| 4 | asr | e2e-ec | GPU | Сервис выполняет распознавание речи. Состоит из 2 компонентов - agent и server. Server - это NVIDIA Triton сервер, на котором работает модель распознавания речи. Agent выполняет роль посредника между API и Server, так как они не могут взаимодействовать напрямую. |  
| 5 | asr | e2e-mic | GPU | Сервис выполняет распознавание речи. Состоит из 2 компонентов - agent и server. Server - это NVIDIA Triton сервер, на котором работает модель распознавания речи. Agent выполняет роль посредника между API и Server, так как они не могут взаимодействовать напрямую. | 
| 6 | asr | vad | GPU | VAD (Voice Activity Detector). Сервис выполняет обнаружение голосовой активности во входном акустическом сигнале, а также диаризацию (группировка фраз по участникам разговора).<br> Этот сервис расставляет временные метки, когда начинается и заканчивается голосовая активность. Затем по этим меткам аудиоданные будут “нарезаны” на части, в которых обнаружена голосовая активность. Это делается, чтобы не тратить ресурсы на анализ и обработку аудиофайла целиком, а только тех частей, в которых зафиксирована речь. <br> VAD-сервис состоит из 2 компонентов - agent и server. Server - это NVIDIA Triton сервер, на котором работают модели, определяющие голосовую активность, и модель, выполняющая диаризацию речи. Agent играет роль посредника между api и server, так как api не может работать с Triton сервером напрямую. <br>На Triton сервере доступны следующие модели:<ul><li>VAD - определяет наличие голосовой активности по паузам в речи.</li><li>Enhanced VAD - улучшенная версия модели VAD.</li><li>Target_Speech - модель, натренированная определять голосовую активность в шумном окружении.</li><li>Отложенный VAD - модель для определения голосовой активности при отложенном распознавании речи.</li><li>Модель, выполняющая диаризацию речи (группировку фраз по участникам беседы).</li></ul> | 
| 7 | asr | lr-mng | CPU | Сервис управления задачами отложенного распознавания. Осуществляет прием запросов от сервиса **api** на создание задачи отложенного распознавания, присвоение задачам уникального идентификатора, хранение состояния задачи, а также отправку задач в Kafka для обработки.|
| 8 | asr | lr-process | CPU | Сервис-воркер по обработке задач отложенного распознавания.|
| 9 | asr | genderage | CPU | Сервис анализирует речь, поступившую на анализ, и определяет:<ul><li>пол говорящего (мужчина/женщина);</li><li>возраст говорящего (взрослый/ребенок);</li><li>эмоциональный настрой говорящего (позитивный/нейтральный/сердитый).</li></ul> Состоит из 2 компонентов - agent и server. <br>Server - это NVIDIA Triton сервер, на котором работает модель, анализирующая речь на вышеуказанные параметры.<br>Agent выполняет роль посредника между api и server, так как api не может работать с Triton сервером напрямую.|
| 10 | asr | antispoofing | GPU | Сервис определяет является ли речь, поступившая на распознавание, подлинной (то есть принадлежит человеку) или это спуфинг-атака (речь была синтезирована искусственно с помощью машины). Состоит из 2 компонентов - agent и server. <br>Server - это NVIDIA Triton сервер, на котором работает модель, определяющая является ли речь настоящей или синтезирована искусственно.<br> Agent выполняет роль посредника между api и server, так как api не может работать с Triton сервером напрямую. |
| 11 | asr | postproc | GPU | Сервис выполняет пост-обработку текста, который получился в результате распознавания речи:<ul><li>расставляет знаки препинания;</li><li>исправляет первую букву на заглавную в тех словах, которые надо писать с большой буквы;</li><li>выполняет денормализацию чисел, то есть изменяет число на его текстовое представление (5 файлов > пять файлов).</li></ul>Состоит из 2 компонентов - agent и server. <br>Server - это NVIDIA Triton сервер, на котором работают 2 модели - одна отвечает за знаки препинания и капитализацию, а другая - за денормализацию чисел. <br>Agent выполняет роль посредника между api и server, так как api не может работать с Triton сервером напрямую.|

## Сервисы tts

Модуль **tts** содержит микросервисы, отвечающие за синтез речи.

| **№** | **Модуль** | **Сервис** | **CPU/GPU**|**Описание**|
| ------ | ------- | ----- |----- |----- |
| 1 | tts | api | CPU | gRPC API для получения услуг синтеза речи. |
| 2 | tts | grpc-gateway | CPU | Сервис выполняет преобразование RESTful запросов в gRPC. |
| 3 | tts | preproc | CPU | Сервис выполняет предобработку текста, который поступил на озвучку:<ul><li>получает морфологические признаки для разрешения морфологической омографии (стЕкла - стеклА);</li><li>расставляет ударения в незнакомых словах;</li><li>выполняет транслитерацию незнакомых английских слов;</li><li>расставляет ударения в контекстных омографах, которые невозможно различить по грамматическим признакам.</li></ul>Состоит из 2 компонентов - agent и server. <br>Server - это NVIDIA Triton сервер, на котором работают модели, отвечающие за вышеупомянутые действия. <br>Agent выполняет роль посредника между api и server, так как api не может работать с Triton сервером напрямую. |
| 4 | tts | acronorm | CPU | Сервис выполняет предобработку текста, который поступил на озвучку:<ul><li>раскрывает сокращения (г. > год/года/году);</li><li>классифицирует точки (нужно ли оставить точку после раскрытия сокращения, если это конец предложения);</li><li>	нормализует числа (определяет как в текущем контексте правильно произнести число).</li></ul> Состоит из 2 компонентов - agent и server. <br> Server - это NVIDIA Triton сервер, на котором работают модели, отвечающие за вышеупомянутые действия. <br> Agent выполняет роль посредника между api и server, так как api не может работать с Triton сервером напрямую. |
| 5 | tts | gradtts | GPU | Сервис выполняет распознавание речи. Состоит из 2 компонентов - agent и server. <br> Server - это NVIDIA Triton сервер, на котором работает модель для синтеза речи. <br> Agent выполняет роль посредника между api и server, так как они не могут взаимодействовать напрямую. |
| 6 | tts | embedding | GPU | Этот сервис необходим для клонирования голоса. Когда в запросе поступает аудио с голосом, который необходимо клонировать, embedding анализирует звуковую волну и преобразует ее в математический вектор (числовой код). Этот код содержит в себе информацию о тембре и уникальных акустических признаках голоса. |

# Шаги по установке Audiogram

##	Шаг 1 – Ознакомьтесь с helm-chart для установки Audiogram

Установка Audiogram в Kubernetes-кластер осуществляется с помощью helm-chart. Ознакомьтесь с параметрами, содержащимися в helm chart по умолчанию, используя команду:

``` bash 
helm show values <путь_к_чарту>
```

##	Шаг 2 – Настройте параметры (values) в helm chart

Создайте или отредактируйте ваш файл *values.yaml*, переопределив в нем необходимые переменные окружения (например, адреса баз данных, уровень логирования и т. д.).

> Примечание: Рекомендуется изменять только те параметры, значения которых отличаются от выставленных по умолчанию.

##	Шаг 3 – Установите Audiogram

Запустите установку Audiogram. Команда ниже создаст пространство имен (namespace), если оно еще не существует, и установит сервис:


``` bash 
helm upgrade --install audiogram <путь_к_чарту> \
  --namespace <namespace> \
  --create-namespace \
  -f <путь_к_values-файлу>
```

##	Шаг 4 –	Проверьте статус установки

Проверьте успешно ли установлен Audiogram, используя команду:

``` bash 
helm -n <namespace> list
```

Пример вывода команды представлен на рисунке:

![](https://raw.githubusercontent.com/mts-ai/audiogram/main/images/installation-status.png)

## Шаг 5 – Проверьте состояние микросервисов

Проверьте, что все поды перешли в состояние Running и готовы к работе. Для этого используйте команду:

``` bash 
kubectl get pods -n <namespace> -w
```

Пример вывода команды представлен на рисунке:

![](https://raw.githubusercontent.com/mts-ai/audiogram/main/images/command-implementation-example.png)

##	Если микросервис не запускается

Если в колонке STATUS вы видите что-то, кроме Running (например, Error или CrashLoopBackOff), выполните следующие команды:

1.	Просмотр подробного описания событий (поможет понять хватает ли ресурсов кластера или нет ли ошибок в конфигурации Kubernetes):

    ``` bash 
    kubectl describe pod <название_пода> -n <namespace>
    ```

2.	Просмотр логов микросервиса (позволит увидеть внутренние ошибки, например, неверный пароль к базе данных):

    ``` bash 
    kubectl logs <название_пода> -n <namespace>
    ```

3. Если в поде несколько контейнеров, добавьте в конец имя контейнера:

    ``` bash 
    -c <имя_контейнера>
    ```

# Настройка резервного копирования

Kubernetes обеспечит отказоустойчивость микросервисов, установленных в кластер.

Настройка резервного копирования баз данных, находящихся на виртуальных машинах снаружи кластера, является критически важной задачей для сохранности данных.

Выбор программного обеспечения для резервного копирования stateful-сервисов Audiogram предоставляется на усмотрение организации, которая будет заниматься установкой Audiogram.

# Обновление Audiogram

Если вышла новая версия Audiogram, не нужно удалять старую. Выполните следующие действия:

1. Установите обновление:

   Выполните команду upgrade. Параметр *--install* гарантирует, что если микросервиса не было, он установится с нуля:

    ``` bash 
    helm upgrade --install --create-namespace --namespace <namespace> audiogram <путь_к_helm_чарту>:<номер_новой_версии>
    ```
2.	Проверьте как проходит установка обновления:
Посмотрите, как Kubernetes по очереди перезапускает обновленные поды (старые удаляются, новые создаются). Для этого используйте команду:

    ``` bash 
    kubectl get pods -n <namespace> -w
    ```

3.	Проверьте историю версий:
Если что-то пошло не так, вы всегда можете посмотреть список всех обновлений (ревизий). Для этого используйте команду:

    ``` bash 
    helm history audiogram -n <namespace>
    ```

# Возврат на предыдущую версию Audiogram

В Helm каждое изменение (установка или обновление) создает новую ревизию. Если после обновления что-то пошло не так, можно одной командой вернуть состояние всех микросервисов к предыдущей удачной ревизии.
Для возврата к стабильной версии Audiogram выполните следующие действия:

1.	Посмотрите историю релизов:
    
    Выполните следующую команду и найдите номер (REVISION) последней стабильной версии Audiogram, которая работала корректно:
  
    ``` bash 
    helm history audiogram -n <namespace>
    ```

2. Выполните возврат к стабильной версии:
   
   Запустите команду rollback, указав номер нужной ревизии:

    ``` bash 
    helm rollback audiogram <номер_ревизии> -n <namespace>
    ```
    Helm автоматически вернет все версии образов и настройки (values) к состоянию этой ревизии.
3.	Проверьте состояние подов:
    
    Убедитесь, что Kubernetes начал «поднимать» старые версии контейнеров. Для этого используйте команду:

    ``` bash 
    kubectl get pods -n <namespace> -w
    ```
4.	Проверьте успешность возврата на выбранную версию:
Нужно убедиться, что в истории появилась новая запись со статусом superseded для «плохой» версии и deployed для текущей. Используйте команду:

    ``` bash 
    helm history audiogram -n <namespace>
    ```
