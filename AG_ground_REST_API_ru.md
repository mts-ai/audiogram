# Справочник REST API компонента ground

&nbsp; &nbsp; 

# Общая информация

Ground — это REST API сервис для чтения данных распознавания речи из медиа-архива. Audiogram использует S3 хранилище для хранения данных, включая:

* Информацию о запросах на асинхронное распознавание речи из аудиофайла, сделанных ранее.
* Результаты асинхронного распознавания речи.
* Исходное аудио, которое использовалось для распознавания речи.
* VAD-метки, которые были определены в исходном аудио.
* Антиспуфинг метки, которые были определены в исходном аудио.

Результат асинхронного распознавания речи сохраняется в S3 хранилище и затем извлекается из него для последующего использования. Остальные данные, хранящиеся в S3, могут использоваться при отладке, если распознавание речи не дало ожидаемых результатов. Аудиозапись также может быть использована для воспроизведения фрагментов, соответствующим распознанным фразам.
Для получения данных из S3 хранилища используется REST API, описываемый в настоящем документе.

 # Аутентификация
   
Для авторизации и аутентификации в сервисе используется механизм JWT токенов. Для получения токена обратитесь к менеджеру продукта. Аутентификация конфигурируется переменной окружения PDP_AUTHORIZATION_ENABLED=true/false.


# Базовый URL-адрес
Текущая версия REST API (v3) располагается по следующему пути:

base-URL = `https://{api_address}/v3/`


# Запросы получения данных из аудиоархива

## Получить список запросов на распознавание речи

Каждый запрос на распознавание речи сохраняется в S3 хранилище, включая сам запрос и его конфигурацию. Прежде чем работать с конкретным запросом необходимо получить список запросов, указав интересующий промежуток дат. Ответ будет содержать ID каждого запроса, ID каждой сессии и ID трассировки, которые затем могут быть использованы в качестве параметров в остальных REST API запросах.

### Метод и конечная точка

**GET {base-URL}/clients/{client_id}/requests**

### Параметры
#### Параметры строки запроса

| Параметр | Тип данных | Обязательность | Описание |
| ------ | ------- | ----- | ----- |
| client_id | string | Да | Уникальный идентификатор клиента (учетной записи)  в системе. |
| dateFrom | string($date-time) | Нет | Дата с которой начать поиск запросов.|
| dateTo | string($date-time) | Нет | Дата, которой закончить поиск. |
| limit | integer | Нет | Максимальное количество выводимых элементов. |
| offset | integer | Нет | Количество пропускаемых элементов. |

### Ответы

**Код 200**. Успешный ответ.  Содержит список запросов.

## Проверить размер и тип аудио файла перед его скачиванием 

### Метод и конечная точка

**HEAD {base-URL}/clients/{client_id}/requests/{request_id}/audio**

### Параметры
#### Параметры строки запроса

| Параметр | Тип данных | Обязательность | Описание |
| ------- | --------- | ------- | ------- |
| client_id | string | Да | Уникальный идентификатор клиента (учетной записи)  в системе. |
| request_id | string | Да | ID конкретного запроса. |

### Ответы
**Код 200**. Аудио файл существует. 

#### Заголовки

| Имя | Тип |  Описание |
| ------- | --------- | ------- | 
| Accept-Ranges | string | Cервер умеет отдавать файл фрагментами (побайтово). | 
| Content-Type | string | Формат аудио файла.  | 
| Content-Length | integer | Размер аудио файла в байтах.  | 

**Код 404**. Аудио файл не найден. 


## Скачать аудио из которого происходило распознавание речи

Исходное аудио также сохраняется в S3 хранилище. При необходимости его можно получить, используя данный метод.

### Метод и конечная точка

**GET {base-URL}/clients/{client_id}/requests/{request_id}/audio**

### Параметры
#### Параметры строки запроса

| Параметр | Тип данных | Обязательность | Описание |
| ------- | --------- | ------- | ------- |
| client_id | string | Да | Уникальный идентификатор клиента (учетной записи)  в системе. |
| request_id | string | Да | ID запроса. |
| Range | string | Нет | Диапазон байтов в аудио файле для загрузки. Указывается в headers. Пример: bytes=0-499 |

### Ответы
**Код 200**. Успешный ответ. Возвращает аудио в формате “audio/wav” (media type).

**Код 206**. Скачан не полный аудио файл, а его фрагмент. Возвращает аудио в формате “audio/wav” (media type).

#### Заголовки

| Имя | Тип |  Описание |
| ------- | --------- | ------- | 
| Content-Range | string | Переданный диапазон байтов относительно общего размера ресурса. Например: bytes 0-1023/5242880. | 
| Content-Length | integer | Количество байтов в теле ответа.  | 

**Код 416**. Сервер не может отдать указанный фрагмент аудио файла, потому что запрошенный заголовок **Range** выходит за пределы реального размера ресурса.

### Ответы

## Скачать текст, полученный в результате распознавания речи

После того как асинхронное распознавание речи выполнено на стороне сервера, результат необходимо загрузить на стороне клиента из S3 хранилища. Для этого используется метод, описываемый в данной секции.

### Метод и конечная точка
**GET {base-URL}/clients/{client_id}/requests/{request_id}/transcript**

### Параметры
#### Параметры строки запроса

| Параметр | Тип данных | Обязательность | Описание |
| ------- | --------- | ------- | ------- |
| client_id | string | Да | Уникальный идентификатор клиента (учетной записи)  в системе. |
| request_id | string | Да | ID запроса. |

### Ответы

**Код 200**. Успешный ответ. Содержит текст и сопутствующую информацию.

| Параметр | Тип данных | Описание |
| ------- | --------- | ------- |
| vaMarks | array | Массив объектов, содержащий список меток голосовой активности (Voice Activity Marks) |
| markType | string | Тип или категория произошедшего события. "VA_MARK_BEGIN" — обозначает начало голосовой активности (момент, когда в аудиозаписи появляется речь, человек начинает говорить или срабатывает детектор речи). В паре с этим типом используется VA_MARK_END — конец голосовой активности.|
| offsetMs | integer | Временное смещение (таймкод) от начала аудиофайла в миллисекундах, на котором зафиксировано событие. |
| hypothesis | object | Объект, содержащий основную гипотезу (результат) распознавания речи для данного отрезка. |
| transcript | string | Сырая (сымитированная) текстовая расшифровка речи.Приводится «как слышится»: строчными буквами, без знаков препинания и без нормализации чисел. |
| normalizedTranscript | string | Нормализованная и форматированная текстовая расшифровка. К ней применены правила пунктуации, капитализации (заглавные буквы) и, при необходимости, преобразование числительных из слов в цифры. |
| startTimeMs | integer| Время начала произнесения фразы от старта аудиозаписи в миллисекундах. |
| endTimeMs | integer| Время окончания произнесения фразы в миллисекундах. |

| status | string | Статус обработки запроса. Значение "fail" указывает на сбой или ошибку при выполнении. |
| code | integer | HTTP-код состояния. 422 (Unprocessable Entity) означает, что сервер понял формат запроса, но содержимые данные неверны или содержат ошибки. |
| timestamp | string (формат date-time) | Точное время формирования ответа об ошибке на сервере в формате ISO 8601 UTC.|
| rqid | string (формат uuid или строка) | Уникальный хэш-идентификатор этого конкретного запроса. |
| locale |  string | Локаль, в которой сервер возвращает текстовые сообщения ("en-US"). |
| alerts |  array (элементы: object) | Массив системных предупреждений или сообщений об ошибках от платформы. |
| level | string | Уровень критичности алерта ("error" — ошибка, блокирующая выполнение запроса). |
| code | integer | Внутренний код категории ошибки. |
| timestamp | string (формат date-time) | Точный момент времени, когда система зафиксировала данный алерт.|
| message | string | Краткое описание алерта.|
| result | object | Объект-контейнер для полезных данных ответа (содержит технические детали ошибки).|
| detail | array (элементы: object) | Массив со списком всех найденных ошибок валидации в запросе.|
| loc | array (элементы: string) | Путь к ошибочному параметру. Массив ["limit"] означает, что ошибка произошла в параметре limit.|
| msg | string | Описание конкретной ошибки. Значение "Invalid value: 2э" говорит о том, что передано невалидное значение с кириллической буквой «э».|
| type | string | Категория ошибки валидации ("type_error" — ошибка типа данных: ожидалось число, а пришла строка с посторонним символом).|

#### Пример ответа
```
{
    "status": "fail",
    "code": 422,
    "timestamp": "2026-07-23T11:50:11.546055Z",
    "rqid": "7fbe7158ea4e742bfb273a4334ceabaf",
    "locale": "en-US",
    "alerts": [
        {
            "level": "error",
            "code": "validation_error",
            "timestamp": "2026-07-23T11:50:11.546065Z",
            "message": "Validation error"
        }
    ],
    "result": {
        "detail": [
            {
                "loc": [
                    "limit"
                ],
                "msg": "Invalid value: 2э",
                "type": "type_error"
            }
        ]
    }
}
```

# Пробы (probes)

Liveness и readiness пробы используются для определения работоспособности и готовности Kubernetes контейнера (сервиса), который предоставляет доступ в S3 хранилище.

## Liveness проб
Определяет работоспособность контейнера.

### Метод и конечная точка

**GET {base-URL}/probes/liveness**

### Параметры
Параметры отсутствуют.

### Ответы
**Код** 200. Успешный ответ.

| Параметр | Тип данных | Описание |
| ------- | --------- | ------- |
 status | string | Статус, показывающий работоспособен ли контейнер или его надо перезапустить. | 

 #### Пример ответа
```
{
    "status": "UP"
}
```

 ## Readiness проб

 Определяет готовность контейнера.

### Метод и конечная точка
**GET {base-URL}/probes/readiness**

### Параметры
Параметры отсутствуют.

### Ответы

**Код: 200**. Успешный ответ.

| Параметр | Тип данных | Описание |
| ------- | --------- | ------- |
 status | string | Статус, показывающий готов ли контейнер принимать трафик или его надо перезапустить. | 

 #### Пример ответа

    "status": "UP"
}
